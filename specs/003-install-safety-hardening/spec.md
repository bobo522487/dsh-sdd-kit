# Feature Specification: 安装与覆盖层的安全性加固（借鉴 AvenCores 补丁器工程实践）

> Describe **what** the system must do and **what it must NOT do**. Keep implementation details (SQL, frameworks, internal classes) out of this document.

## 1. User Story & Intent

- **作为**一名在自己的项目里反复运行 `/sdd-setup`、并会手工微调 `.specify/templates/overrides/` 与扩展配置的 DSH 用户，**我希望**安装层能准确判断「目标处于什么状态」、在写入前留好可回滚的快照、并且永不顺着符号链接写到项目之外，**从而**在升级 Spec Kit 或调整模板时既不丢手工定制，也不会因为一次坏写入把项目或 DSH 启动搞坏。

**背景与动机**：本特性借鉴 `trustybird/AvenCores-open-antigravity-patcher`（客户端补丁器）中与「多宿主探测 + 非破坏性覆盖 + 原子替换 + 可升级与回滚」相关的工程实践。该项目的二进制逆向与签名部分**不在**借鉴范围内。

**用户场景**

- 主要场景（状态可辨）：用户第一次运行 `/sdd-setup`，模板被写入；随后用户手工改过模板，再次运行 `/sdd-setup`，系统识别为「用户自定义」，保留文件不动并在报告中说明；上游模板版本升级后再次运行，系统识别为「上游已更新、本地仍旧版」，给出明确提示与可执行的刷新方式，而不是静默跳过。
- 回滚场景：一次安装后 DSH 或 Spec Kit 行为异常，用户执行一次回滚操作，安装产物回到上一次成功安装的内容，并得到「回到了哪个版本」的报告。
- 多候选目录场景：机器上同时存在多个上游镜像/候选目录（默认路径、环境变量指定、历史残留），系统按「同一真实路径只算一次、最近活跃者优先」选出唯一目标，而不是按硬编码顺序盲选。
- 异常写入场景：目标路径是符号链接、写入过程中进程中断、或目标位于项目目录之外，系统拒绝或安全放弃该次写入，项目与项目外文件均保持原样。
- 上游契约漂移场景：上游 Spec Kit 发布新版后参数或契约发生变化，夜间/手动集成测试在无人值守的情况下第一时间失败并指出漂移点。

## 2. Functional Requirements (EARS Format)

Write every requirement using EARS syntax so it maps 1-to-1 to automated tests:

**A. 幂等状态检测（四分类 + `unknown` 兜底，共五个判定取值）**

- `REQ-01`: **WHEN** 系统准备写入任一受管安装产物（EARS 模板覆盖文件、扩展注册项、技能产物）**THE SYSTEM SHALL** 先判定其状态，且判定结果 MUST 落在以下四类之一（判定范围限于本插件拥有写权的产物；写权在上游 `specify` CLI 的产物只映射 CLI 退出码，见 §5「写入范围收敛」）：`not_installed`（不存在）、`installed_consistent`（存在且与本版本随包内容逐字节一致）、`user_modified`（存在但与随包内容不同，且无法归因于已知旧版本）、`stale_upstream`（存在且与某个已知历史版本一致，但落后于当前随包版本）。
- `REQ-02`: **WHEN** 判定结果为 `installed_consistent` **THE SYSTEM SHALL** 跳过写入，并在报告中标记为 unchanged，且 MUST NOT 触碰文件时间戳与内容。
- `REQ-03`: **WHEN** 判定结果为 `user_modified` 且用户未显式要求覆盖 **THE SYSTEM SHALL** 保留文件原样，在报告中说明「检测到用户自定义」并给出显式覆盖的方式，且 MUST NOT 静默覆盖。
- `REQ-04`: **WHEN** 判定结果为 `stale_upstream` **THE SYSTEM SHALL** 在报告中同时给出「当前随包版本」与「本地内容所属版本」，并说明可用的刷新动作；是否自动刷新 MUST 由显式参数决定，默认 MUST NOT 自动改写。
- `REQ-05`: **IF** 状态无法判定（例如文件存在但不可读、内容既非任何已知版本也非可比较状态）**THE SYSTEM SHALL** 归入 `unknown` 并在报告中明确标记，MUST NOT 将其当作 `not_installed` 直接写入。

**B. 多候选目录的选择**

- `REQ-06`: **WHEN** 同一类目标存在多个候选目录（默认路径、环境变量指定路径、历史残留路径）**THE SYSTEM SHALL** 先按解析后的真实路径去重，再以「最近修改时间较新者优先」排序，选出唯一目标。
- `REQ-07`: **IF** 多个候选的真实路径与最近修改时间完全相同 **THE SYSTEM SHALL** 以稳定的确定性次序（声明顺序）决胜，使同一台机器上的重复运行得到同一结果。
- `REQ-08`: **WHEN** 选中的候选目录与用户显式指定的一致 **THE SYSTEM SHALL** 在报告中记录该目录的绝对路径与选择依据（显式指定 / 唯一候选 / 最近活跃）。

**C. 备份刷新与一键回滚**

- `REQ-09`: **WHEN** 系统即将覆盖任一已存在的受管安装产物 **THE SYSTEM SHALL** 在覆盖前保留一份可还原的快照，且快照 MUST 标明其来源版本或内容标识。
- `REQ-10`: **IF** 已存在的快照与「覆盖前目标内容」不一致（说明目标已被上游或用户改变，旧快照已过期）**THE SYSTEM SHALL** 刷新该快照，使快照始终等于最近一次覆盖前的内容。
- `REQ-11`: **WHEN** 用户请求回滚 **THE SYSTEM SHALL** 用最近一次有效快照还原对应产物，报告还原了哪些文件与快照来源版本，且 MUST NOT 触碰未被该快照覆盖的其他文件。
- `REQ-12`: **IF** 不存在任何可用快照 **THE SYSTEM SHALL** 明确报告「无可回滚的快照」，并以未成功状态结束，MUST NOT 伪造还原结果。

**D. 原子写入与符号链接防护**

- `REQ-13`: **WHEN** 写入任一受管安装产物 **THE SYSTEM SHALL** 先在同一目录内创建隔离临时文件，写入完成并落盘后才以单次替换操作生效，使读者永远看不到半写状态。
- `REQ-14`: **IF** 写入过程中发生异常或中断 **THE SYSTEM SHALL** 清理残留临时文件，目标文件保持写入前的内容。
- `REQ-15`: **IF** 目标路径的任一层是符号链接，或解析后的真实路径位于项目根之外（用户显式指定的路径除外）**THE SYSTEM SHALL** 拒绝该次写入并说明拒绝原因，MUST NOT 沿链接写入。
- `REQ-16`: **WHEN** 一次安装包含多个产物 **THE SYSTEM SHALL** 使单个产物的失败不阻断其余产物的处理，并在最终报告中按产物列出成功 / 跳过 / 失败与原因。

**E. 面向真实上游的集成验证**

- `REQ-17`: **WHEN** 维护者触发上游集成验证（夜间计划或手动触发）**THE SYSTEM SHALL** 在真实环境中安装真实上游 `specify` CLI 并执行一次真实的初始化与扩展安装，验证参数与契约仍然成立。
- `REQ-18`: **IF** 上游集成验证失败 **THE SYSTEM SHALL** 明确指出失败的具体上游交互（哪个命令、哪个参数或哪个契约字段），且该失败 MUST NOT 阻塞日常单元测试的通过判定。
- `REQ-19`: **WHEN** 上游集成验证因网络或凭据不可用而无法执行 **THE SYSTEM SHALL** 将其报告为「未执行（环境不可用）」，MUST NOT 报告为通过。

## 3. Non-Goals & Hard Constraints (业务禁区)

- **Out of Scope（不在范围内）**：二进制补丁与逆向、客户端 JS 注入、签名校验、代理/证书处理（AvenCores 的其余部分）；重写 Spec Kit 或 Superpowers 的任何上游逻辑；新增第三个用户可见技能；把 `tasks.md` 勾选纳入本特性；自动重启 DSH；自动切换既有项目的 integration；对 `.specify/` 之外的业务源码做任何改写。
- **Forbidden Behavior（禁止行为）**：
  - MUST NOT 复制或替换 DSH profile 内已安装的插件副本（章程原则 I 的硬边界）；本特性的备份/回滚只作用于**项目内安装产物**与**本插件随包内容**。
  - MUST NOT 以「文件存在」作为唯一判据决定跳过或覆盖（这正是本特性要消除的行为）。
  - MUST NOT 在未显式要求时覆盖被判定为 `user_modified` 的文件。
  - MUST NOT 以「回滚成功」的报告掩盖实际未还原的事实。
  - MUST NOT 新增 npm 运行时依赖；临时文件、落盘、替换、真实路径解析 MUST 使用运行时既有能力。
  - MUST NOT 让安装层在失败后留下半写文件或残留临时目录。
- **Performance / Compatibility Bounds（性能 / 兼容性边界）**：
  - 状态判定与候选选择在单次 `/sdd-setup` 内的额外耗时不超过 2 秒（不含网络）。
  - 回滚为单次操作、无交互提示，典型耗时不超过 5 秒。
  - 兼容 Node.js >= 18、ESM、跨平台（Linux / macOS / Windows）；平台受限用例（如符号链接）MUST 显式跳过并注明原因。
  - 现有 `/sdd-setup`、`/sdd-update` 的既有输出字段与成功/失败语义 MUST 保持向后兼容；新增字段为增量。

## 4. Acceptance Criteria

- [ ] `AC-01`（REQ-01/02）：对同一项目连续运行两次 `/sdd-setup`；第二次报告模板覆盖文件为 `installed_consistent` / unchanged，且该文件内容与修改时间均未变化。
- [ ] `AC-02`（REQ-03）：手工修改模板覆盖文件后运行 `/sdd-setup`；文件保持手工内容不变，报告明确标出「用户自定义」并给出显式覆盖方式。
- [ ] `AC-03`（REQ-04）：将覆盖文件替换为某个已知历史版本内容后运行；报告同时给出「当前随包版本」与「本地所属版本」，默认未发生改写；显式要求刷新后才更新内容。
- [ ] `AC-04`（REQ-05）：构造一个存在但不可读的目标文件；报告为 `unknown`，未发生写入，且未以失败掩盖状态。
- [ ] `AC-05`（REQ-06/07/08）：在临时目录中构造三个候选（其中两个通过符号链接指向同一真实路径，另一个更新）；选择结果唯一、为最近活跃者，且报告中出现所选绝对路径与选择依据；重复运行时选择结果一致。
- [ ] `AC-06`（REQ-09/10）：先安装一次，再修改随包内容并再次覆盖；覆盖前快照被刷新为「本次覆盖前内容」，快照带有内容标识，且旧快照不会覆盖更新的快照。
- [ ] `AC-07`（REQ-11/12）：执行回滚；受管产物逐字节回到快照内容，报告列出还原文件与快照来源版本；在无快照的干净项目中执行回滚，得到明确的「无可回滚快照」未成功结果。
- [ ] `AC-08`（REQ-13/14/15）：在目标写入过程中注入异常；目标保持原内容、目录内无残留临时文件；将目标替换为指向项目外的符号链接后重试，写入被拒绝且链接指向的文件未被修改。
- [ ] `AC-09`（REQ-16）：令其中一个产物写入失败；其余产物仍被处理，最终报告按产物列出成功 / 跳过 / 失败与原因，整体状态为未成功。
- [ ] `AC-10`（REQ-17/18/19）：手动触发一次上游集成验证；在真实环境中完成真实上游安装与扩展安装并给出通过/失败结论；失败时输出指明具体命令与契约点；在无网络环境中报告「未执行（环境不可用）」。

### Success Criteria

- 用户无需阅读内部状态即可从报告判断每个安装产物处于四类状态中的哪一类，以及下一步该做什么。
- 手工定制在任何一次 `/sdd-setup` 之后都不丢失（除非用户显式要求覆盖）。
- 任意一次覆盖都可被还原到覆盖前内容，且还原范围严格限定在快照覆盖的文件。
- 项目外的文件在任何异常场景（符号链接、路径逃逸、写入中断）下都不会被修改。
- 上游契约漂移可在一次夜间/手动集成验证内被发现，且不干扰日常测试结论。

## 5. Assumptions and Dependencies

- 借鉴对象 `trustybird/AvenCores-open-antigravity-patcher` 仅作为工程实践来源；本特性不引入其代码、依赖或许可证义务。
- 受管安装产物指：`.specify/templates/overrides/` 下的模板覆盖文件、`.specify/extensions.yml` 中本扩展的注册项、以及由上游 `specify` 生成的命令技能产物；其内容事实来源仍为仓库内随包文件（章程原则 I）。
- **写入范围收敛（规划期确认）**：本插件只对 `.specify/templates/overrides/spec-template.md` 拥有写权，因此只有它走本特性的四分类判定、快照与原子写；`.specify/extensions.yml` 的注册项与 `.dsh/skills/speckit-*` 由上游 `specify` CLI 写入，本插件只映射 CLI 的退出码并在报告中呈现结果，不自行判定、不写入、不留快照（章程原则 I 禁止平行逻辑）。
- 「已知历史版本」通过随包携带的版本标识（如内容指纹或版本号）识别；不要求联网查询历史版本。
- 备份/回滚的状态目录位于项目内、与被保护文件同层（`.specify/templates/overrides/.backup/`），并由目录内的自忽略文件保证不入库（不依赖宿主项目的 `.gitignore`，也不改写它）。
- 真实上游集成验证依赖网络与 `uv`/`specify` 的公开安装渠道；无网络环境按 `REQ-19` 报告为未执行。
- 现有 `/sdd-setup` 的步骤编排与 `/sdd-update` 的两层上游语义不变；本特性只加固其写入路径与状态判定。

## 6. Key Entities

- **安装产物（Managed Artifact）**：一个可被安装/覆盖的文件或注册项；字段为标识、目标路径、随包内容标识、当前状态分类。
- **状态判定结果（Status Verdict）**：`not_installed` / `installed_consistent` / `user_modified` / `stale_upstream` / `unknown`，附判定依据（内容比对、版本标识、不可读原因）。
- **候选目录（Candidate Root）**：同类目标的候选位置；字段为声明顺序、解析后真实路径、最近修改时间、是否被选中与选择依据。
- **快照（Snapshot）**：覆盖前内容的副本；字段为覆盖对象、内容标识、来源版本、创建时间、是否过期。
- **安装报告条目（Install Report Entry）**：按产物记录结果（written / unchanged / skipped_user_modified / skipped_stale / refreshed / failed）与原因。
- **集成验证结果（Integration Verification Result）**：通过 / 失败（含具体上游命令与契约点）/ 未执行（环境不可用）。
