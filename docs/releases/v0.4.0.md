## 概要

`dsh-sdd-kit` v0.4.0 把执行纪律的注入方式从「桥接技能」迁移到 **Spec Kit 原生 Extension 钩子**。从这一版起，日常开发与缺陷修复**只需敲 Spec Kit 原生命令**——`/sdd-implement` 已被删除，Superpowers 纪律由 `before_implement`、`after_implement`、`before_bug_fix`、`after_bug_fix` 四条强制钩子自动织入。

这是一次**破坏性变更**：旧的 `/sdd-implement` 入口不再存在，也不保留废弃提示页。迁移只需重新运行一次 `/sdd-setup`。

## 新增

- **内置 Spec Kit 扩展**（`spec-kit-extension/`）：标准 `extension.yml` 清单 + 四个钩子命令文件，通过 `specify extension add --dev` 装入 `.specify/extensions/`，由 Spec Kit 自己负责生命周期、版本兼容检查与钩子调度。
- **`sdd_upstream` 新 action `install_hooks_ext`**：一次且仅一次调用 `specify extension add --dev <dir> --force`，返回扩展 id/版本、`integration`、技能落盘目录、四条钩子事件清单与 `restartRequired`。新增可选参数 `extensionDir`。
- **`/sdd-setup` 七步工作流**：新增第 5 步安装内置扩展；第 7 步汇总必须报告扩展版本、四个钩子事件、`integration` 与落盘目录。
- **默认 `integration=dsh`**：`specify init` 默认使用 Spec Kit 官方的 `dsh` integration，生成的技能落在 DSH 原生技能根 `.dsh/skills`，不再依赖 `.claude/skills` 与第三方 skills-manager 插件才能被 DSH 发现。
- **integration 不一致提示**：在既有 `claude` 项目上，`/sdd-setup` 会明确指出不一致、给出 `specify integration switch dsh` 与影响范围，但**不会**自动改写你的项目布局。

## 变更

| 事件 | 触发时机 | 自动加载的上游技能 |
|---|---|---|
| `before_implement` | `/speckit.implement` 写第一行源码前 | `test-driven-development`、`systematic-debugging` |
| `after_implement` | 全部任务完成后 | `verification-before-completion`、`requesting-code-review` |
| `before_bug_fix` | `/speckit-bug-fix` 改源码前 | `systematic-debugging`、`test-driven-development` |
| `after_bug_fix` | 修复报告写完后 | `verification-before-completion`、`requesting-code-review` |

- 四条钩子均为 `optional: false`（强制），前置 `priority: 5`、后置 `priority: 15`，不写 `condition`。
- 钩子只按名称引用上游 DSH 技能，**不内联任何纪律正文**；唯一来源仍是 `~/.dsh/upstream/superpowers/skills`。
- 章程升至 **v3.0.0**：原则 I 的技能上限从三个降回两个（`sdd-setup`、`sdd-update`）。

## 移除

- **`/sdd-implement` 技能**（`skills/sdd-implement/`）：目录已删除，README、`cordis.patch.yml` 与章程中不再作为执行入口出现。特性实现改用原生 `/speckit.implement`，缺陷修复改用原生 `/speckit-bug-fix`。

## 行为保证

- **幂等**：重复运行 `/sdd-setup` 或重装扩展，同一事件下不会出现重复条目，也不会留下旧版本声明的孤儿条目。
- **不碰上游**：`specify extension add/remove` 不改写 `.specify/templates/`、`.specify/scripts/` 或 Spec Kit 核心命令模板。
- **全局开关不动**：强制语义仅由每条钩子的 `optional: false` 承担，`settings.auto_execute_hooks` 保持安装前的取值。
- **失败关闭**：上游 Superpowers 技能目录缺失时，钩子报出缺失的技能名、完整路径与修复命令 `/sdd-setup` 后停止，绝不静默跳过纪律。
- **只报告不切换**：`specify_init` 仅在项目尚无 `.specify/` 时调用；既有项目永不被自动重跑 init 或自动切换 integration。
- **卸载干净**：`specify extension remove superpowers-hooks --force` 后 `extensions.yml` 回到 `installed: []` / `hooks: {}`，配置备份在 `.specify/extensions/.backup/`。
- **不用 Runtime Events**：本版刻意只使用 Hooks 层，未注册任何 `pre_tool_use` 类事件或硬门禁拦截。

## 破坏性变更

- **`/sdd-implement` 已删除**。若你的笔记或脚本仍在调用它，请改用 `/speckit.implement`（特性）与 `/speckit-bug-fix slug=<slug>`（缺陷）。
- **技能数量从 3 降至 2**（`sdd-setup`、`sdd-update`）。Host 工具数量不变，仍为 2（`sdd_upstream`、`sdd_bridge`）。
- **新建项目默认 `integration=dsh`**。既有 `claude` 项目不会被自动迁移，需你显式执行 `specify integration switch dsh`。

## 升级步骤

```bash
# 1. 重新 add 同一个来源即可升级（git 依赖的锁文件指向具体 commit，
#    单靠 update 会报 "Already up to date"）
dsh plugin --profile web add github:bobo522487/dsh-sdd-kit

# 2. 重启 DSH（工具代码有变更，必须重启才能加载 install_hooks_ext）

# 3. 在项目里重装扩展与上游镜像
/sdd-setup
```

升级后确认：

```bash
specify extension list
# 期望：✓ Superpowers Hooks (v0.1.0)
#       Commands: 4 | Hooks: 4 | Priority: 10 | Status: Enabled
```

## 安装

```bash
dsh plugin --profile web add https://github.com/bobo522487/dsh-sdd-kit
```

或使用下方附件：

```bash
dsh plugin --profile web add ./dsh-sdd-kit-0.4.0.tgz
```

安装后**重启 DSH**，然后在项目中运行 `/sdd-setup`。

## 使用

```
/speckit.specify → /speckit.clarify → /speckit.plan → /speckit.tasks → /speckit.analyze
/speckit.implement          # before/after_implement 钩子自动注入 TDD 与两阶段自审

/speckit-bug-assess "<symptom>" slug=<slug>
/speckit-bug-fix slug=<slug>   # before/after_bug_fix 钩子自动注入调试纪律与验证衔接
```
