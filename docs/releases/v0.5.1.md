# v0.5.1

## 概要

v0.5.1 是 v0.5.0 的迁移修复补丁：把安装产物移出版本控制后，从"产物曾入库"的旧仓库升级上来的项目会同时丢失 `.dsh/skills/` 下的原生 Spec Kit 命令技能；而 `/sdd-setup` 按 REQ-15 对既有布局跳过 `specify init`，导致没人重建这些文件。v0.5.1 让这一重建进入 setup 状态机，成为可断言、幂等的一步。

对外表面不变：**2 个技能 + 2 个 Host 工具 + 1 个 Spec Kit 扩展**，章程保持 v4.0.0。

## 修复

- 新增 `sdd_upstream(action: "ensure_integration_commands")`：
  - 检查 `<skillsDir>/speckit-implement/SKILL.md` 是否存在；存在则直接跳过（零 CLI 调用）。
  - 缺失时依次尝试 `specify integration upgrade <key>`、`specify integration install <key>`，每步后重新检查；成功即返回 `repaired: true` 与实际执行的 `commands`。
  - 两步都无法恢复时返回结构化失败 `{ code: 'E_INTEGRATION_COMMANDS', message, hint }`，不抛异常。
- `runSetup` 在 `specify_init` 决策**之后**、两个扩展安装**之前**新增步骤 `integration_commands`（`performed` / `skipped` / `failed`）。失败使整次 setup 返回 `ok: false`，但**不阻断**后续扩展安装（与 REQ-11 的"失败不阻断"一致）。
- 未修改的行为：REQ-15（既有布局不重跑 init）、REQ-16（integration 切换必须显式 opt-in）、四钩子 `optional: false`、`settings.auto_execute_hooks` 不变。

## 升级步骤

```bash
# 1. 包管理器重新解析 git 依赖
dsh plugin --profile web update dsh-sdd-kit --latest

# 2. 重启 DSH

# 3. 在项目里重跑 setup（会自行修复缺失的原生命令技能）
/sdd-setup
```

验收：`specify extension list` 应显示 `Superpowers Hooks (v0.1.0)`，`Commands: 4 | Hooks: 4`；`.dsh/skills/` 应包含 9 个原生命令 + 3 个 bug 命令 + 4 个钩子命令。

## 验证

- `npm test`：**51 tests / 51 pass / 0 fail / 0 skip**。
- 真实 CLI 端到端：在临时项目 `specify init --integration dsh` 后删除 `.dsh/skills/`，`ensure_integration_commands` 成功恢复全部 9 个原生命令技能，二次调用零 CLI 调用。
- 迁移场景实测：本仓库由 v0.4.x 升级到 v0.5.0 后 `.dsh/skills/` 曾仅剩 7 项；本修复覆盖该场景。
