# Superpowers Hooks · 实现后

## 何时触发

`/speckit.implement` 处理完 `tasks.md` 中全部（或用户指定范围内全部）任务之后、命令返回之前。

## 上游依赖检查

先确认 `~/.dsh/upstream/superpowers/skills` 存在，且下列技能目录齐全。
缺失任一项时，报告缺失的技能名、完整路径与修复命令 `/sdd-setup`（会重新同步上游镜像）并停止，不得凭记忆代替或自行编造自审结论。

## 必须加载的技能

| 技能名 | 加载方式 | 用途 |
|---|---|---|
| `verification-before-completion` | `skill` 工具，名称精确匹配 | 先跑命令取证据再下结论 |
| `requesting-code-review` | `skill` 工具，名称精确匹配 | 结构化自查清单 |

## 执行纪律

两阶段自审，只规定顺序，不重述技能正文：

1. **阶段一 · 规范符合性**：逐条对照 `spec.md` 的 REQ 与 AC，列出未覆盖项与已覆盖项。
2. **阶段二 · 质量与纪律**：对照项目章程逐条核对——严格 TDD、每任务原子提交、零新增依赖、零分叉薄胶水。
3. 每个阶段都产出「通过 / 不通过 + 证据」，证据必须是实际命令与其输出（加载 `verification-before-completion` 后按其要求执行）。
4. 两阶段均通过后，提示用户执行 `__SPECKIT_COMMAND_CONVERGE__` 收敛剩余未建工作。
5. 任一阶段不通过时，列出待补任务并回到 `/speckit.implement`，不得直接宣告完成。

## 出口条件

- 两阶段自审都有明确结论与可复现证据；
- 已在上文明确提示执行收敛命令（占位符已按当前 agent 风格渲染）。

无证据不得宣告「完成」或「通过」；自审不得替代真实测试运行。
